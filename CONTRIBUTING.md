# Contributing

Use a branch and pull request, describe the behavior change, and run the tests
listed in the README. Keep hardware-specific changes separate from server changes
where practical. Test the packed frame format and timezone boundaries when
changing rendering or forecast selection.

Do not include real credentials, coordinates, private network configurations,
firmware builds or personal dashboard screenshots. Use the fictional demo and
explicit test fixtures. Review staged files with `scripts/check_public.py` and a
secret scanner. Disclose security issues privately through GitHub's private
vulnerability reporting if enabled; otherwise ask for a private contact without
posting credentials or exploit details publicly.

Original contributions use the repository's Unlicense. Preserve all third-party
license notices and document the source of any newly bundled dependency or asset.
